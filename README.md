## 시작

이 작업 환경에는 의존성을 설치했습니다. Windows에서는 루트의 `start-workroom.cmd`를 실행하세요. 이관한 작업 데이터는 `.workroom/`에 보관되어 있습니다. 새로 설치한 환경에서는 빈 데이터로 시작합니다.

일반 개발 환경에서는 Node.js 24 이상과 pnpm을 준비한 뒤:

```sh
pnpm install --ignore-scripts
node node_modules/electron/install.js
pnpm start
```

`npm install`도 가능하지만 재현 가능한 의존성 설치에는 포함된 `pnpm-lock.yaml`을 사용하세요.

## 아직 연결하지 않은 것

앱 종료 중의 백그라운드/원격 운영, 임의 빌드·패키지 스크립트 실행과 의존성 설치, 호스팅 배포, 다른 데스크톱 클라이언트 자동 설정, 인스톨러 및 자동 업데이트. 판단을 저장해도 에이전트가 자동 재개되지 않습니다. Codex 수집기는 공식 훅 입력 형식과 별도 프로세스로 검증했으며, 실제 Codex 작업에서의 자동 호출은 최초 훅 신뢰 후 확인해야 합니다.

## 지속 운영과 대상별 편집

1. 제품 **설정 → 지속 운영**에서 주기와 하루 시작 한도를 저장합니다. 기본은 꺼져 있습니다.
2. 수정안까지 이어가려면 자동 수정안을 켜고 고정 Node 테스트 경로·실행 허용을 지정합니다. 실패 보완은 최대 1회입니다. 원본 반영은 변경 검토 뒤 사용자가 결정합니다.
3. **개요**에서 최근 관측, 시작·대기 이유, 발견 문제와 연결 작업을 확인합니다. 변화가 없으면 모델을 호출하지 않습니다. 앱 실행 중만 운영하며 놓친 일정은 한 번으로 합칩니다.
4. **포트폴리오**에 대상별 강조점과 연결 제품을 저장한 뒤 **대상에 맞게 정리**를 누릅니다. 새 결과의 자동 편집도 별도로 켤 수 있습니다. 사례 선정·작성 뒤 다른 세션이 주장을 검토합니다. 직접 쓴 문장·순서·제외를 보존합니다.

[구현 계획서](outputs/autonomous-operations-plan.md)와 [구현·검증 기록](outputs/autonomous-operations-implementation.md)에 정책, 실행 한도, 확인 범위를 정리했습니다.

## 첫 내장 조사

1. 제품 메뉴 오른쪽 위의 **일 맡기기**에서 원하는 결과를 적고 **먼저 조사**를 선택합니다. 모든 제품 메뉴에서 같은 요청창이 열립니다.
2. 연결 전이면 요청창의 **연결 설정**을 누릅니다. 요청과 선택 범위가 보관되며 설정 화면에서 원래 요청창으로 돌아갈 수 있습니다. **일 맡기기** 제출 버튼은 연결 후 사용할 수 있습니다.
3. **ChatGPT 계정으로 로그인**한 뒤 모델을 선택·저장합니다. **짧은 요청으로 연결 확인**은 실제 모델 요청 한 번을 사용합니다. 준비가 되면 보관한 요청으로 돌아오며 실행 버튼을 눌러 맡깁니다.
4. 작업 상세에서 단계, 인용 파일, 제공한 이전 기록과 결과를 확인합니다. 검토를 마친 조사에서는 **이 조사로 수정안 맡기기**로 제안된 다음 작업을 가져올 수 있습니다.

로그인 없이도 기존 데이터 열람과 MCP 수집은 가능합니다. 창을 닫으면 로컬 실행기도 종료하며 자동으로 백그라운드에 남지 않습니다.

## 첫 수정안

1. 제품의 **개요 → 일 맡기기**에서 바꾸려는 동작과 완료 기준을 적고 **수정안까지 작성**을 선택합니다.
2. 실행할 Node 내장 테스트가 있으면 제품 기준 파일 경로를 지정하고 실행을 허용합니다. 선택한 테스트는 수정 전후에 동일하게 실행되며 에이전트가 바꾸지 못합니다.
3. 작업에서 변경 전후 코드, 앱이 실행한 검사, 별도 세션의 검토 의견을 확인합니다.
4. **검토한 수정본 반영**을 누르면 원본 버전을 다시 확인한 후 적용합니다. 기능 테스트를 생략했거나 지원하지 않는 형식은 미확인으로 표시하며 적용 전에 이를 확인해야 합니다.
5. 원본 변경으로 반영이 막히면 **최신 원본으로 새 수정안**을 선택할 수 있습니다. 기존 수정안은 보존됩니다.

Node.js 24 이상이 필요하며 `WORKROOM_NODE`로 실행 파일을 지정할 수 있습니다. 현재 검사는 별도 소스 복사본에서 실행하고 파일 접근·자식 프로세스를 제한하지만, 악의적인 코드를 안전하게 실행하는 OS·네트워크 샌드박스는 아닙니다. 의존성을 복사하거나 설치하지 않으므로 외부 패키지가 필요한 테스트는 실패할 수 있습니다. 자동 검사 밖의 형식은 별도 검증이 필요합니다.

## 데이터

기본 위치는 프로젝트의 `.workroom/workroom.sqlite`입니다. `WORKROOM_DATA_DIR`로 바꿀 수 있습니다. 앱과 MCP에 동일한 값을 지정해야 합니다. 인증 정보는 같은 데이터 디렉터리의 `credentials/openai.credential`에 OS 암호화 상태로 저장합니다. 다른 컴퓨터에 복사해도 같은 계정으로 복호화된다는 보장은 없으며 재로그인이 필요할 수 있습니다. SQLite WAL과 낙관적 버전 검사를 사용하여 동시 수정 시 조용히 덮어쓰지 않습니다. 작성 중인 요청은 이 데이터 디렉터리의 Electron 프로필(localStorage)에 제품별로 보관하며 MCP에 아직 제출한 작업이 아닙니다. 백업은 앱과 MCP를 종료한 뒤 데이터 디렉터리를 통째로 복사하세요.

## MCP

앱의 ‘MCP 연결 → 연결 설정 보기’에 현재 위치에 맞는 stdio 설정이 있습니다. Node.js 24 이상을 사용합니다. MCP를 켜기 전에 앱에서 접근할 제품 폴더를 등록하세요. 설정을 표시하는 기능이며 외부 앱 설정을 자동 변경하지 않습니다.

```sh
pnpm mcp
```

이 명령은 stdio MCP 서버이므로 일반 텍스트를 입력하는 대화창이 아닙니다. MCP 클라이언트가 프로토콜로 연결해야 합니다. 로그를 stdout에 출력하지 않습니다.

## 검사

```sh
pnpm test
```

56개 테스트가 저장 지속성, 동시 수정, 읽기 전용 점검, 결정·기록의 원자성, 제품별 참조 범위, 출처 보존, HTML 이스케이프, 공개 내용 분리, 실제 MCP stdio 연결, 보고 재전송·수정 버전, 자동 초안 반영과 편집 보호, Codex 이벤트 수집·설정 보존·Windows 훅 명령, 실행 연결 정정과 과거 참조 버전 보존을 확인합니다.

새 실행 검사는 역할 인계, 중지 후 늦은 응답, 파일 버전 변경, 병렬 한도, 인증 실패 재시도 억제, 지식 단계만 재개, 경로 제한과 인증 갱신 직렬화를 확인합니다. 실제 Pi SDK에는 결정적 모의 모델 응답을 넣어 명시적 도구 실행과 스킬 자동 수집 차단을 확인합니다. 라이브 모델 성공을 대체하는 검사는 아닙니다.

조사에서 파생된 후속 작업은 같은 제품의 근거 확인을 마친 조사만 연결하며, 원래 조사와 다음 작업 제안이 실제 실행 인계에 포함되는지 확인합니다.

수정 실행 검사는 실제 Node 테스트의 수정 전 실패·수정 후 통과, 원본 보존, 정확한 수정본 반영, 원본·복사본 변경 차단, 중복 반영 방지와 반영 도중 종료 복구를 확인합니다. 선택 테스트 보호, 모든 변경 파일의 별도 검토, 같은 제품의 실행 직렬화, 원본 쓰기 권한 차단, 로컬 검사 중지를 포함합니다.

Electron 화면은 별도로 Playwright의 Electron API로 등록 → 점검 → 판단 → 결과 기록 → 포트폴리오 → HTML 저장 → 재시작 복원을 확인했습니다. OS의 파일 선택 창만 검사 경로로 대체하고, 실제 IPC·서비스·SQLite·내보내기를 사용했습니다. 테스트 데이터는 `work/` 아래에 격리됩니다.

`pnpm check:app`은 예제 데이터로 실제 Electron 앱을 띄우는 화면 흐름 검사 11개를 실행합니다(약 1분). 화면을 바꾸면 함께 실행하세요. [검사 스크립트 안내](scripts/checks/README.md)

`pnpm lint`는 ESLint로 가져오지 않은 이름과 쓰이지 않는 import·변수를 찾습니다. 화면 코드를 구조만 바꿀 때는 `scripts/render-snapshot.mjs`로 전후의 모든 화면 HTML을 비교하세요. `pnpm check:app`이 `work/`에 남긴 예제 DB로 약 1,100개 화면 상태를 그립니다.

```sh
node scripts/render-snapshot.mjs save before.json
node scripts/render-snapshot.mjs save after.json --same-as before.json
node scripts/render-snapshot.mjs compare before.json after.json
```

`scripts/checks/check-live-report.cjs`는 별도 MCP 프로세스에서 보고를 전송해 실제 Electron의 자동 갱신·편집 병합·충돌 비교·제외 보존·구독 중단·내보내기 검토 보호를 검사합니다. 상세 계약은 [작업 보고 연결](outputs/report-flow.md)에 있습니다.

`scripts/checks/check-codex-setup.cjs`는 격리된 제품에서 설정 저장 → 생성된 훅 프로세스 → 앱 표시 → 초안 반영 → 수집 중단을 검사합니다. 실제 Codex의 이벤트 발생은 대체했으며 신뢰 설정을 우회하지 않았습니다. [Codex 자동 수집 안내](outputs/codex-capture.md).

`scripts/checks/check-change-app.cjs`는 실제 Electron에서 변경 비교 → 실제 검사 결과 → IPC로 예제 원본 반영 → 결과·반영 기록 저장과 테스트 실행 동의 입력을 확인합니다. 수정·검토의 모델 응답은 결정적 모의 응답이며 Node 검사는 실제 실행입니다.

`scripts/checks/check-overview-app.cjs`는 격리된 예제 데이터를 사용한 실제 Electron에서 개요 분류·결과 중복 제거, 로그인 전 요청, 설정 왕복·재로드·제품 전환 시 초안 보존, 조사에서 후속 요청으로 연결, 기존 초안 복원, 기록 제공 이력과 대상별 초안 이동, 좁은 어두운 화면과 일반 편집 보호를 확인합니다. `outputs/app-overview-*.png`는 이 검토 데이터의 화면입니다. 이 자동 UI 검사는 모의 데이터로 진행합니다. 실제 계정·모델은 [별도 실제 실행](outputs/live-model-verification.md)으로 확인했습니다.

```text
src/core/       저장·검증·제품·작업·지식·포트폴리오
src/desktop/    Electron 메인과 제한된 preload API
src/runtime/    Pi·OAuth·실행 대기열·소스 복사·검사·버전별 반영
src/renderer/   로컬 화면 · app.js 시작, controller.js 화면 전환·요청 흐름·API·render, shell.js 화면 뼈대 HTML, screen-state.js 다시 그릴 때 스크롤·입력·포커스 보존, click-actions.js·form-actions.js·field-events.js 이벤트 처리, state.js 상태, *-views.js·*-ui.js 화면별 HTML, html.js 공통 조각
src/mcp/        같은 핵심 기능에 연결하는 stdio MCP
tests/          저장 및 MCP 통합 검사
scripts/checks/ 실제 Electron 화면 흐름·실제 계정 검사
outputs/        기획·UX 문서와 시작 안내
outputs/archive/ 더 이상 기준이 아닌 이전 기획·조사 자료
work/           검사용 임시 데이터 (Git 제외)
```

렌더러의 Node 직접 접근을 끄고, context isolation과 sandbox를 사용하며, IPC 송신 화면을 검증합니다. 외부 페이지로 이동하거나 새 창을 열지 않습니다. [Electron IPC](https://www.electronjs.org/docs/latest/tutorial/ipc), [Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)

MCP는 고정된 SDK 버전으로 stdio 도구를 제공합니다. [공식 MCP TypeScript SDK 서버 문서](https://ts.sdk.modelcontextprotocol.io/server)

초기 로컬 저장에는 Node의 내장 SQLite 모듈을 사용합니다. [Node SQLite](https://nodejs.org/api/sqlite.html)
